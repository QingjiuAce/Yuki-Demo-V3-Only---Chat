# Yuki - Demo

Yuki 模型系列的**第一代 Demo**：纯 `numpy` 实现的 GPT-like Transformer Decoder，
只跑 **CPU**，只包含**最基础的训练算法**。

- 架构：Transformer Decoder（GPT-like），**Pre-Norm**
- 规模：**52W 级（约 52 万参数）**
- 框架：**numpy 手写前向 + 手写反向传播**（不依赖 PyTorch / PaddlePaddle）
- 本代目标：把「能训练、能收敛、能生成」的最基本算法跑通，不做训练优化

> 这是新系列的开始。上一代 `Shithon-mini` 里的那些训练优化方案（学习率预热、
> 余弦退火、混合精度、梯度累积、阶梯回退重启、早停、LoRA、memmap 缓存等）
> **本代全部没有引入**，后续版本再按需逐代加。

## 快速开始

### 1. 放语料

把 `.txt` 语料丢进 `data/` 目录（可以放多个文件，会自动合并）。

- **每个非空行算一篇文档**，编码时各自用 `<bos>` / `<eos>` 包住
  （想改成「整个文件一篇文档」加 `--whole-file-docs`）。
- **行首序号会被自动去掉**：`1 今天也要开心` → `今天也要开心`。
  只匹配「数字 + 空白」，所以 `2026年我们…` 这种不会被误伤；
  想保留序号加 `--keep-line-numbers`。
- 清洗**只发生在内存里**，不会改动 `data/` 下的原始语料文件。

**对话语料**（想做对话版就用这种）：每行以 `用户：` / `Yuki：` 开头，一问一答成对出现，
段与段之间空一行。`train.py` 会自动识别成 dialogue 模式，编码时插入
`<|user|>` / `<|yuki|>` 角色 token：

```
用户：今天写代码好累啊
Yuki：别总盯着屏幕，眼睛会累哦

用户：我刚打了个喷嚏
Yuki：清久酱打喷嚏时Yuki会想你
```

- 规则：一段对话以「用户」行开头，遇到下一个「用户」行就开始新的一段。
- 想强制指定形态：`--corpus-mode dialogue|plain|auto`（默认 auto 自动检测）。

### 2. 训练

```bash
python train.py                       # 默认 3000 步
python train.py --steps 5000 --batch-size 32
python train.py --lr 1e-3 --max-vocab 6000
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--data-dir` | 语料目录（默认 `data`） |
| `--out-dir` | 输出目录（默认 `checkpoints`） |
| `--steps` | 总训练步数（默认 3000） |
| `--batch-size` | batch 大小（默认 16；样本太少时会自动降低） |
| `--seq-len` | 序列长度（默认 128） |
| `--lr` | 学习率（默认 3e-3） |
| `--max-vocab` | 词表上限（默认 4200） |
| `--log-every` / `--save-every` / `--sample-every` | 打印 / 存档 / 样例生成间隔 |
| `--keep-tokenizer` | 复用已有 `tokenizer.json`（默认每次按当前语料重建） |
| `--keep-line-numbers` | 保留行首序号（默认去掉） |
| `--whole-file-docs` | 整个文件作为一篇文档（默认每个非空行一篇） |
| `--init-from` | 用已有 checkpoint 的权重**热启动/微调**（优化器从零开始；语料变大时会自动「只追加」扩展词表并扩展嵌入矩阵） |
| `--resume` | 从 `out-dir/latest.npz` **断点续训**（连优化器状态、步数、loss 曲线一起恢复） |
| `--resume-from` | 指定要续训的 checkpoint（默认 `out-dir/latest.npz`） |
| `--no-shuffle-docs` | 关闭每轮重排文档顺序（默认开启） |

### 继承上一代权重（热启动 / 断点续训）

```bash
# 断点续训：被打断后接着练（--steps 是总步数，不是"再练几步"）
python train.py --steps 8000 --resume

# 热启动：拿旧权重做初始化，优化器从零开始
python train.py --steps 3000 --init-from 'D:\AI\Yuki - Demos\Yuki - Demo V2\V2 - 2610152356\latest.npz'
```

- `--resume` 恢复：权重 + **优化器一阶/二阶动量** + 步数 + loss 曲线 + 随机数状态。
  分别存在 `latest.npz` / `latest.opt.npz` / `latest.json` 里；旧格式缺 `opt.npz` 时会提示并退化成热启动。
- `--init-from` 只恢复权重，优化器重新开始 —— 适合「在旧模型基础上喂新数据」。
- ✅ **加语料不再需要从头训练**：继承权重时分词器走「**只追加**」模式 —— 旧字符的 id
  一个都不动，新字符按词频追加到末尾；同时把 checkpoint 的嵌入矩阵扩展（旧行原样保留、
  新行随机初始化，优化器动量对新行补零，lm_head 因绑定自动跟随）。
  实测：V2.1 权重 + 12 个新字符的扩展语料热启动，**loss 从 0.416 起步**
  （随机初始化应为 ln(1450)≈7.28），且旧题回答保持不变。
- ⚠️ **仍然必须配同一份基础 `tokenizer.json`**（脚本优先用 `--out-dir` 下的，没有就用
  checkpoint 旁边的）；如果它与 checkpoint 记录的词表大小不符会直接报错。
- 经验法则：

  | 改动 | 能否继承权重 |
  |---|---|
  | 继续训练（结构、语料都不变） | ✅ `--resume`（含优化器动量、步数、loss 曲线） |
  | **加语料**（结构不变） | ✅ **可以**（只追加词表 + 自动扩展嵌入矩阵） |
  | 加宽 / 加层 / 换 MLP 类型 | ❌ 所有矩阵形状都变，只能从零 |
  | 换 BPE 分词器 | ❌ 分词单位变了，只能从零 |

  👉 所以建议把「加宽 / 换分词器」这类**必然重训**的改动攒到一起做，只重训一次。

- ⚠️ **加语料时用 `--resume` + 调低学习率，不要用 `--init-from` + 原学习率。**
  实测对照（同样是「上一代权重 + 新语料」）：

  | 做法 | base 500 | 寒暄 150 | 数字 175 |
  |---|---|---|---|
  | `--init-from` + lr 3e-3 | 94.2% | 89.3% | 78.9% |
  | **`--resume` + lr 5e-4** | **99.4%** | **98.0%** | **93.7%** |

  `--init-from` 会**冷启动优化器**：Adam 在 `t=0` 时偏差校正让第一步更新幅度接近满学习率，
  直接作用在已训练好的权重上会把旧知识冲散（灾难性遗忘）。`--resume` 恢复了一阶/二阶动量，
  更新平稳得多。**学习率降到 1/6 左右（3e-3 → 5e-4）**，`--steps` 写总步数。

  ```powershell
  python train.py --resume-from <上一个>\latest.npz --out-dir <新目录> --steps <原步数+增量> --lr 5e-4
  ```

训练输出示例（V2：500 组对话语料，实测）：

对话效果（`python chat.py`，低温/贪心解码）：

| 清久酱 | Yuki |
|---|---|
| 今天有没有想我一点点 | Yuki今天也超喜欢清久酱 |

| 我今天想吃顿好的犒劳自己 | 今天也要对自己好一点 |

500 组问答的全量贪心评测：**单轮 99.8%**、**前置 1 / 2 / 4 轮随机对话 100% / 99.8% / 100%**。

### ⚠️ 一条重要经验：每轮重排语料顺序（`shuffle_docs`）

第一版按**固定顺序**把 500 组对话拼成一条长序列去切块，踩了个大坑：

- 训练 loss 掉到 **0.005**（近乎完美），在训练上下文里逐字准确率 **99.7%**；
- 但真正生成时（只给一个问题、没有前文）完全答对率只有 **3~5%**，首字准确率 **35.7%**。

原因：模型走了捷径 —— 用「上一段对话」推断自己在语料里的位置，然后直接吐出
下一段的答案，**根本没学会「看问题选答案」**。固定顺序让它能靠序号作弊。

改成**每个 epoch 重新打乱文档顺序**（`shuffle_docs=True`，默认开启）之后：

| 场景 | 修之前 | 修之后 |
|---|---|---|
| 单轮完全答对 | 4.8% | **99.8%** |
| 首字答对 | 35.7% | **100%** |
| 前置 1 / 2 / 4 轮随机对话 | 0% / 0% / 0% | **100% / 99.8% / 100%** |

代价是训练 loss 从 0.005 变成 0.34 —— 那才是这个任务的**真实难度**。
**结论：判断小模型有没有真的学到东西，要看「生成时的准确率」，不能只看 loss。**

装不下的更早轮次会被丢掉。注意 `max_seq_len=128` 是字符级的，上下文很短，

## 记忆分 vs 留出分（评测口径）

**问题**：`eval_chat.py` 原来 8 组测试里有 7 组来自训练语料 —— base / para / chitchat /
chat_var / numeric / robust / multiturn 全都在 `Demo_chat_v24.txt` 里出现过。
它们是**记忆分**：模型做得好，只能说明它背得熟，不能说明它「会」。
唯一沾点边的是 `robust`（删字/加字变体），而它恰好是分数最低的一组。

**解法**：加了一份**固定留出集**，训练时排除，单独存放。

| 项 | 值 |
|---|---|
| 文件 | `data/_holdout/holdout.txt` |
| 内容 | 864 段 / 1,024 轮（占原语料 10%） |
| 抽法 | 按**段**随机，种子 `20261016`（`--holdout-mode segment`） |
| 训练排除 | 每轮 merge 都会把这些段从训练语料里剔掉 |

几条设计上的坑，都已经处理掉了：

1. **留出集必须固定、跨代可比**。如果每次 merge 都重新抽，语料一变大留出集就变了，
   各代的「留出分」根本不是同一批题。所以留出集**只在第一次生成**，之后
   `merge_corpus_v21.py` 只是把它从训练语料里排除（要重抽得显式加 `--refresh-holdout`）。
2. **不能与训练集重题**。抽出来的段里若有问句在训练集出现（必然被背过），整段剔除 ——
   本次就剔了 20 段。
3. **这份留出分测的是「同话题的新变体」**。因为答案是任意的，把整个话题都留出去，
   模型只会 0 分、且永远涨不动。所以按「段」留出：留出段里有 809/864（94%）的答案
   在训练集里出现过，模型要答对的是「同一个意思的新说法/新错法」。这才是我们要迭代的能力。
4. **小心词表外的字**。留出集里有 11 个字不在训练语料中
   （`启 壳 布 批 泉 猛 糙 腐 膜 芦 饺`）。从头训练时这些字会变成 `<unk>`，
   含它们的题必然答不对、留出分偏低；续训/继承权重不受影响（词表只追加）。
   想避免就在从头训练时带上完整词表（`--keep-tokenizer` + 旧的 `tokenizer.json`）。
   `merge_corpus_v21.py` 会把这个数字打出来。

### V2.4 实测：一次「被污染的留出集」长什么样

留出集是 V2.4 训完之后才切出来的，所以 V2.4 对它**是见过的**。实测（贪心解码）：

| 组 | 准确率 | 性质 |
|---|---|---|
| base / para / chitchat / chat_var / numeric | 99.8 / 99.8 / 97.3 / 98.9 / 98.3% | 记忆分 |
| multiturn 多轮末轮 | 82.7% | 记忆分 |
| robust 删 1 字 / 多 1 字 | 55.5% / 72.5% | ✅ 真·没见过的扰动 |
| **holdout 留出集(单轮)** | **98.3%**（793/807） | ⚠️ 污染 |
| **holdout 留出集(多轮末轮)** | **100.0%**（57/57） | ⚠️ 污染 |
| — 记忆分（宏平均） | 96.1% | |
| — 留出分（宏平均） | **99.1%** | ⚠️ 不可信 |

- **留出分 99.1% 比记忆分 96.1% 还高。** 这在诚实的留出集上几乎不可能，
  是「留出集被污染」的铁证 —— 因为留出集里那 864 段，V2.4 训练时**逐字见过**。
- 对照组是 `robust 删 1 字` = **55.5%**（同一个问题、只是真没见过的错法）。
  **98.3% 与 55.5% 之间那 43 个点，就是「背」与「会」的距离。**
- 所以 `eval_chat.py` 现在会在「留出分 > 记忆分」时直接告警，免得被漂亮数字骗过去。
- V2.4 这一格数字留着当反例；**第一个可信的留出分要等一次从头训练**。

> ⚠️ **诚实提醒**：V2.4 训练时还没有留出集，所以它对这 864 段是「见过」的，
> **V2.4 的留出分偏乐观**。留出集只有从下一次**从头训练**开始才真正干净。
> 像阶段 1 那样 `--resume` 继承 V2.4 权重，仍然带着对留出集的记忆。
> 想拿到第一个可信的留出分，得等一次 from-scratch 训练（阶段 2 的 V3 本来就要重训）。

### 一条命令跑一轮迭代

```bash
# 只切留出集（从现有语料，不加新片段）
python merge_corpus_v21.py --base data/Demo_chat_v24.txt --no-parts \
    --out <临时输出> --holdout 0.1

# 完整一轮：augment -> merge(含留出集) -> train -> eval，并记进 runs/iterations.csv
python run_iteration.py --base data/Demo_chat_v24.txt --parts data/_parts6 \
    --out data/Demo_chat_v25.txt --resume --steps 22000 --lr 5e-4 --tag v2.5
python run_iteration.py ... --dry-run          # 先看看会执行哪些命令

# 只想重训 + 评测
python run_iteration.py --skip-merge --resume --steps 22000 --lr 5e-4 --tag v2.5
```

`run_iteration.py` 会做四件事：跑增强（可选）→ 调 merge 切/排除留出集 →
**把旧的顶层训练语料归档到 `data/_raw/`**（否则 `train.py` 会同时读两份、语料翻倍）→
调 train → 调 eval，并把「**robust 删1字/多1字**（字面鲁棒性的成绩单）/ 记忆分 / 留出分 / 差距」
追加到 `runs/iterations.csv`。

```bash
python eval_chat.py --json runs/eval_v2.5.json    # 单独跑评测、导出明细
```

**测试组怎么指定**（换新语料时用这个，别再依赖写死的路径）：

```bash
python eval_chat.py --set base=data/my.txt --set para=data/para_*.txt
python eval_chat.py --sets-file data/eval_sets.txt   # 每行一句 NAME=GLOB，# 开头为注释
```

不给 `--set` 时才会去用遗留的 V2 分组（且**只保留真实存在的**）；
一份都没有就退化成「从训练语料抽样」当记忆分组。
**任何文件缺失都只跳过并提示，不会崩**（旧版会因为写死路径直接 `FileNotFoundError`）。
`robust` 会自动从第一个测试组抽前 200 条、现造「删 1 字 / 多 1 字」变体
（可用 `--robust-src` 指定来源、`--robust-n` 改条数）。
每个测试组会自动分流：单轮段直接比对，多轮段用金标准前文测末轮。

**结论：判断有没有真变强，先看 `robust`（那是真没见过的错法），再看留出分。**
记忆分涨了不算数。

## V2.5 语料：错字剂量 2× → 4×

先说清 V2.4 的语料结构（按「答案家族」看）：每个答案有 **4 个规范问法**
（1 个原句 + 3 个同义）＋ **8 个扰动问法**（每个规范问法 2 种错法）＝ 12 条。
「剂量不够」正是 V2.4 留下的短板（`删 1 个字` 只有 55.5%）。
所以 V2.5 把每个问句的错法**从 2 种加到 4 种**，并给**多轮段的最后一轮**也加扰动。

| 项 | V2.4 | V2.5 |
|---|---|---|
| 训练语料 | `Demo_chat_v24.txt` · 8,845 段 / 10,211 轮 | `Demo_chat_v25.txt` · **14,553 段 / 18,491 轮** |
| 每问错法 | 2 种 | **4 种** |
| 多轮末轮扰动 | 无 | **有**（+1,010 段） |
| 新增片段 | `_parts5`（5,562 段） | `_parts6/perturb3.txt`（6,572 段） |
| 词表 | 1,646 | 1,646（没引入新字符） |

生成命令（`augment_perturb.py` 新增了三个开关）：

```bash
python augment_perturb.py --input data/_raw/Demo_chat_v22.txt \
    --out data/_parts6/perturb3.txt --per-turn 2 --seed 20261017 \
    --include-multiturn --avoid data/Demo_chat_v24.txt
```

- `--per-turn 2`：每个问句再生成 **2 种互不重复**的错法（叠加 V2.4 的 2 种 = 4 种）。
- `--include-multiturn`：多轮段的**最后一轮**也扰动，前面几轮原样保留当上下文。
- `--avoid`：不生成语料里已经有的问句。不做这件事的话，新扰动会和旧扰动撞车，
  等于把同一条又背一遍 —— 本次 3,286 个目标全部凑够 2 种、段级重复 0。
- 扰动输入固定用 **V2.2 的规范问句**（`data/_raw/Demo_chat_v22.txt`），**不是**累加后的语料 ——
  否则会生成「扰动的扰动」，退化成乱码。

另外，merge 时会把留出集的「被考问句」（单轮问句 / 多轮末轮）和「多轮上下文问句」分开统计：
本次被考问句 **0 条泄漏**；有 160 条上下文问句在训练集里出现过，但那只是喂进去当历史的，
不直接计分（而且正是我们要的那种「同一段历史、换一种问法」）。

## 模型结构

```
Token Embedding
  -> N x [ RMSNorm -> 多头因果自注意力 -> 残差
           RMSNorm -> MLP(GELU)         -> 残差 ]     # Pre-Norm
  -> RMSNorm
  -> 输出投影（与词嵌入共享权重，tie weights）
```

| 项 | 值 |
|---|---|
| 隐藏维度 D | 64 |
| 层数 L | 9 |
| 注意力头数 H | 4（head_dim = 16） |
| MLP 中间维度 F | 162 |
| MLP 类型 | **SwiGLU**（3 矩阵门控：`W2(silu(W1 x) * (W3 x))`）；`config.py` 里 `mlp` 可切回 `"gelu"` |
| 最大序列长度 | 128 |
| 归一化 | RMSNorm（eps=1e-6） |
| 激活函数 | SiLU（SwiGLU 门控内） |
| 位置信息 | **RoPE 旋转位置编码**（rope_theta=10000，只旋转 Q/K） |
| 输出层 | 与词嵌入权重绑定（tie weights） |
| bias | 全部关闭 |

### 参数量

```
参数量 = V x D                          词嵌入 / 输出投影（共享）
       + L x (4D^2 + k*D*F + 2D)        每层：注意力 4 个方阵 + MLP（k=3 SwiGLU / k=2 GELU）
       + D                              末尾 RMSNorm

当前配置（D=64 L=9 F=162 SwiGLU，V=1,438）：
  结构部分（与词表无关）= 9 x (4x64^2 + 3x64x162 + 2x64) + 64 = 428,608
  词表部分 = 1,438 x 64 = 92,032
  合计 = 520,640（52.1W）
```

| 词表 V | 参数量（D64 L9 F162 SwiGLU） | 说明 |
|---|---|---|
| 1,000 | 492,608（49.3W） | 小语料 |
| 1,200 | 505,408（50.5W） | |
| **1,438** | **520,640（52.1W）** | **当前语料（V2.1）** |
| 2,000 | 556,608（55.7W） | |
| 3,000 | 620,608（62.1W） | 大字符集 |

> **参数量随词表变化**：字符级分词器的词表 = 语料里出现的不同字符数。
> 换语料后想继续维持 52W，就微调 `ff_dim`：`F ≈ (520000 − V·D − L·(4D²+2D) − D) / (L·k·D)`。
>
> 几组可选结构（都约 52W）：
>
> | 配置 | 参数量 | 备注 |
> |---|---|---|
> | D=64 L=9 F=162 **SwiGLU**（当前） | 520,640（52.1W） | 结构等价 LLaMA-mini，为导 GGUF 铺路 |
> | D=64 L=9 F=242 GELU | 519,424（51.9W） | 同深度但换成 2 矩阵 GELU |
> | D=64 L=5 F=256 GELU | 316,992（31.7W） | V1/V2 用的结构（对照用） |
>
> **换 MLP 类型是结构变更**：`mlp` 会影响每个 MLP 的矩阵个数与形状，旧权重无法复用
> （脚本会直接报形状错误，不会静默出错）。

## 训练算法（本代实现的范围）

| 环节 | 实现 |
|---|---|
| 前向 | numpy 手写：嵌入 → 5×(RMSNorm→MHA→残差→RMSNorm→MLP→残差) → RMSNorm → 输出投影 |
| 注意力 | 多头 + 因果掩码（上三角加 -1e9），`softmax(QK^T/√d)V` |
| 损失 | softmax + 交叉熵合并实现，对每个位置预测下一个 token |
| 反向 | **全部手写**：softmax、RMSNorm、GELU、注意力、残差、权重绑定处的梯度累加（`np.add.at`） |
| 优化器 | **Adam**（β1=0.9, β2=0.999, eps=1e-8），可选 weight_decay |
| 梯度裁剪 | 全局范数裁剪，阈值 1.0 |
| 存档 | 每 `save_every` 步存 `latest`，loss 新低时存 `best`（含 config 的 json 元信息） |
| 监控 | 每 `log_every` 步打印 loss / ppl / 梯度范数 / 速度；每 `sample_every` 步生成一次样例 |

### 本代**故意没有**实现的部分

学习率预热、余弦退火、混合精度（AMP）、梯度累积、阶梯训练 / 回退重启、
早停与验证集、LoRA、Dropout、KV-Cache、重复惩罚、memmap 数据缓存、断点续训。

这些都属于「优化」，等基础版本稳定后再逐代加。

### ⭐ 贯穿整个系列的一条规律：变体覆盖数 = 泛化能力

同一个坑在四个层面上重复出现，每次都是「模型学会了捷径、而不是意思」：

| 代 | 模型学到的「捷径」 | 解法 | 效果 |
|---|---|---|---|
| V1 | 靠**语料顺序**推断自己在第几段，直接吐下一段答案 | 每 epoch 重排文档（`shuffle_docs`） | 单轮 4.8% → 99.8% |
| V2 | 每个答案只有 **1 种问法**，只会逐字匹配 | 每答案补 3 种问法 | 新问法 5.3% → 97.2% |
| V2.3 | 每个问题只有 **1 种错法**，把那种错法背下来 | 用 `augment_perturb.py` 加错字 | 删字 48.0% → **55.5%** |
| V2.4 | 是**剂量**不够 | 每问 2 种错法 | 删字 46.0% → **55.5%**，且精度创新高 |

👉 **小模型的泛化能力 ≈ 同一个意思的变体覆盖数。** 想让它「听懂意思」，就得把同一个意思
用尽可能多的形式喂进去 —— 换说法、打错字、加口语词、改语序都算。

## 已知限制

1. **无 KV-Cache**：生成时每步重算整段上下文，长文本会变慢。
2. **字符级分词**：词表随语料增长，英文/代码的压缩率不如 BPE。
3. **训练 loop 里没有验证集**：`train.py` 只报训练 loss，看不到训练中途的泛化情况，
   只能练完再评测；而且 **loss 低不代表生成对**（见下文 shuffle_docs 那一节，
   这是本项目踩过的最大的坑）。评测侧的留出集已经有了（见「记忆分 vs 留出分」），
   但**还没接进训练 loop** —— 想在训练中途看到留出分，需要自己定期调 `eval_chat.py`。
4. **续训不保留 epoch 内的批次位置**：权重/优化器/步数/RNG 都能恢复，但每个 epoch 会重新打乱
   语料并重新切块，所以续训后从新的一个 epoch 开始（对最终效果没有影响，只是曲线会略有跳变）。
5. **多轮分两种口径**：给定语料里**正确的历史**时末轮 92.4%；换成**模型自己的回答**当历史，
   第1轮 93.8% → 第2轮 92.5% → 第3轮 88.8%（缓降）；而**语料外的多轮序列**
   （单句合理、组合没见过）第 3 轮左右会退化成复读。想要更稳需要更多、更长（4~6 轮）的多轮样本。
6. **泛化仍然有限**：52.1W 参数 + 3,385 轮语料，主要还是在「记住」。语料里没有的说法时好时坏
   （`我今天加班到很晚` → `别熬太晚，Yuki会担心`，但 `想你了` 仍会答偏）。
   **删 1 个字只有 58.5%**，字面鲁棒性是最顽固的短板。想要真泛化，语料得再上一两个数量级。
7. **上下文只有 128 字符**：多轮聊 4~5 句就开始丢最早的轮次；要真正多轮需要 `max_seq_len` 256+。
